7.2 · 금액을 읽기 좋게 표시

금액을 읽기 좋게 표시

기본 문법

TO_CHAR(숫자, '숫자 포맷')
포맷의미
9숫자 표시 자리
0숫자가 없는 자리도 0으로 표시
,천 단위 구분
FM채움 공백 제거

• 잔액을 천 단위 쉼표와 원 단위로 표시

SELECT account_number, balance,
       TO_CHAR(balance, 'FM999,999,999,999,990') || '원' AS "잔액 표시"
  FROM accounts
 WHERE customer_id = 1001
ORDER BY account_number;
표시 자릿수 확인

숫자에 비해 포맷의 자릿수가 부족하면 #으로 표시될 수 있음. 조회할 금액 범위에 맞게 자릿수 지정.

• 표시 자릿수가 부족한 경우

SELECT account_number, balance,
       TO_CHAR(balance, 'FM999,990') || '원' AS "잔액 표시"
  FROM accounts
 WHERE customer_id = 1001
ORDER BY account_number;
7.3 · 값에 따라 표시 문구 변경

값에 따라 표시 문구 변경

기본 문법

CASE 컬럼명
    WHEN 비교값1 THEN 결과값1
    WHEN 비교값2 THEN 결과값2
    ELSE 기본값
END
  • 단순 CASE: 컬럼의 값이 비교값과 같은지 확인.
  • ELSE: 일치하는 값이 없을 때 반환할 값.
  • END: CASE 표현식의 끝.

• 값이 같은지 비교하는 CASE

SELECT account_number, status,
       CASE status
           WHEN '정상' THEN '정상 계좌'
           WHEN '휴면' THEN '휴면 계좌'
           WHEN '해지' THEN '해지 계좌'
           ELSE '상태 확인'
       END AS "상태 표시"
  FROM accounts
ORDER BY status, account_number;
계좌 상태를 보고서용 문구로 표시.
7.4 · 조건에 따라 잔액 구간 분류

조건에 따라 잔액 구간 분류

기본 문법

CASE
    WHEN 조건1 THEN 결과값1
    WHEN 조건2 THEN 결과값2
    ELSE 기본값
END

• 조건에 따라 잔액 구간 표시

SELECT account_number, balance,
       CASE
           WHEN balance IS NULL THEN '잔액 미확인'
           WHEN balance < 0 THEN '음수 잔액'
           WHEN balance = 0 THEN '잔액 없음'
           WHEN balance < 50000000 THEN '5천만원 미만'
           ELSE '5천만원 이상'
       END AS "잔액 구간"
  FROM accounts
ORDER BY balance, account_number;
위에서부터 확인하여 처음 만족한 조건의 결과를 반환.
음수 → 0원 → 5천만원 미만 → 5천만원 이상 순서로 구분.
  • NULL은 IS NULL로 확인.
  • 조건에 맞지 않고 ELSE도 없으면 NULL 반환.
  • 반환할 값은 문자끼리 또는 숫자끼리 맞추어 작성.
7.5 · NVL로 NULL 대체하기

NVL로 NULL 대체하기

기본 문법

NVL(확인할 값, NULL일 때 대체값)
  • 값이 있으면 원래 값 반환.
  • NULL이면 지정한 대체값 반환.
유의사항
✓ 확인할 값과 대체값의 데이터 타입을 맞추어 작성.
✓ 문자에는 문자, 숫자에는 숫자, 날짜에는 날짜 사용.
✓ 다른 타입은 자동 변환될 수 있으나, 변환할 수 없으면 오류 발생.

• 전화번호가 없으면 안내 문구 표시

SELECT customer_id, customer_name, phone_number, email,
       NVL(phone_number, '전화번호 없음') AS "연락처 정보"
  FROM customers
ORDER BY phone_number NULLS FIRST, customer_id;
7.6 · 등록된 정보 중 하나 선택

등록된 정보 중 하나 선택

기본 문법

COALESCE(값1, 값2, 대체값)
  • 왼쪽부터 확인하여 NULL이 아닌 첫 값을 반환.
  • 모든 값이 NULL이면 NULL 반환.

• 등록된 연락정보를 우선순위에 따라 표시

SELECT customer_id, customer_name, phone_number, email,
       COALESCE(phone_number, email, '등록 정보 없음') AS "등록 연락정보"
  FROM customers
ORDER BY phone_number NULLS FIRST, customer_id;
전화번호 → 이메일 → 등록 정보 없음 순서로 표시.
7.7 · NVL2와 DECODE 읽기

NVL2와 DECODE 읽기

기존 SQL에서 만날 수 있는 표현. CASE와 비교하여 역할 확인.

NVL2 · 값의 유무에 따라 선택

기본 문법

NVL2(확인할 값, NULL이 아닐 때 결과, NULL일 때 결과)

• NVL2로 연락처 등록 여부 표시

SELECT customer_id, customer_name, phone_number,
       NVL2(phone_number, '등록', '미등록') AS "전화번호 등록 여부"
  FROM customers
ORDER BY phone_number NULLS FIRST, customer_id;
DECODE · 값이 같은지 비교

기본 문법

DECODE(컬럼명, 비교값1, 결과값1,
비교값2, 결과값2,
기본값)

• 기존 Oracle SQL의 DECODE 읽기

SELECT account_number, status,
       DECODE(status,
              '정상', '정상 계좌',
              '휴면', '휴면 계좌',
              '해지', '해지 계좌',
              '상태 확인') AS "상태 표시"
  FROM accounts
ORDER BY status, account_number;
범위나 여러 조건을 표현할 때는 CASE 사용.

NVL2 vs. CASE vs. DECODE 비교

구분NVL2 함수CASE 표현식DECODE 함수

판단 조건NULL / NULL 아님대소 비교·범위·AND / OR·NULL 등특정 값과 같은지 비교
분기 개수2가지여러 WHEN … THEN으로 다중 분기 가능비교값·결과값 쌍으로 다중 분기 가능

7.8 · 실습 문제

실습 문제

문제와 결과 예시를 보고 SELECT문을 작성하세요.

실습 1. 보고서용 잔액 표시

1001번 고객의 계좌번호·계좌종류·잔액을 조회하세요. 잔액은 천 단위 쉼표와 원을 붙이고 제목을 잔액(원)으로 지정하세요. 원래 잔액 내림차순, 계좌번호 오름차순으로 정렬하는 SELECT문을 작성하세요.

실습 2. 연락정보 표시 우선순위 변경

고객번호·고객명·등록 연락정보를 조회하세요. 이메일이 있으면 이메일, 없으면 전화번호, 둘 다 없으면 등록 정보 없음으로 표시하세요. 이메일 오름차순(NULL 먼저), 고객번호 오름차순으로 정렬하는 SELECT문을 작성하세요.

실습 3. 해지 여부 구분

계좌번호·상태·해지 구분을 조회하세요. 해지는 해지 계좌, 정상과 휴면은 미해지 계좌, 그 외는 상태 확인으로 표시하세요. 상태, 계좌번호 오름차순으로 정렬하는 SELECT문을 작성하세요.

실습 4. 잔액 구간별 확인 목록

계좌번호·잔액·잔액 구간을 조회하세요. NULL은 잔액 미확인, 0원 미만은 음수 잔액, 0원은 잔액 없음, 0원 초과 1천만원 미만은 1천만원 미만, 1천만원 이상은 1천만원 이상으로 표시하세요. 잔액, 계좌번호 오름차순으로 정렬하는 SELECT문을 작성하세요.

실습 5. 고객 연락정보 누락 점검

고객번호·고객명·전화번호·이메일·점검 결과를 조회하세요. 둘 다 NULL이면 연락정보 없음, 전화번호만 NULL이면 전화번호 미등록, 이메일만 NULL이면 이메일 미등록, 둘 다 있으면 모두 등록으로 표시하세요. 전화번호와 이메일 오름차순(각각 NULL 먼저), 고객번호 오름차순으로 정렬하는 SELECT문을 작성하세요.

7.9 · 단원 마무리

단원 마무리

표현기억할 핵심
TO_CHAR(숫자, 포맷)숫자를 읽기 좋은 문자로 표시. 계산·금액 정렬에는 원래 숫자 사용.
단순 CASE값이 같은지 비교하여 결과 선택.
조건 CASE위에서부터 확인하여 처음 참인 조건의 결과 반환.
ELSE · NULL해당 조건이 없으면 ELSE 적용. ELSE도 없으면 NULL.
NVLNULL이면 지정한 대체값 반환. 확인할 값과 대체값의 타입을 맞추어 작성.
COALESCENULL이 아닌 첫 값을 왼쪽부터 선택.
NVL2 · DECODE기존 SQL을 읽을 때 역할을 확인할 보충 표현.

기본 문법

CASE
    WHEN balance IS NULL THEN '미확인'
    WHEN balance < 0 THEN '음수 잔액'
    ELSE '0원 이상'
END
7.10 · 이틀간의 학습 정리 · Chapter 1~7

이틀간의 학습 정리 · Chapter 1~7

단원배운 내용업무에 적용
1. SQL과 데이터베이스 이해하기테이블·행·열, 기본키(PK)·외래키(FK)데이터 한 건의 의미와 테이블 관계 이해
2. 원하는 데이터를 찾아보자SELECT · FROM · 별칭 · 산술식 · DISTINCT필요한 컬럼을 골라 조회
3. 필요한 데이터만 골라내기WHERE · 비교 · IN · LIKE · NULL · ORDER BY대상과 조건을 정하고 결과 정렬
4. 데이터를 더 편하게 다루기문자·숫자·날짜 함수 · NVL값을 계산하고 날짜·빈 값을 알기 쉽게 표시
5. 데이터를 숫자로 읽다COUNT · SUM · AVG · GROUP BY · HAVING건수·합계·평균을 구하고 그룹별 비교
6. 흩어진 데이터를 하나로 연결하기JOIN · OUTER JOIN · Oracle (+)고객·계좌·영업점 정보를 연결
7. 데이터를 원하는 형태로 가공하기금액 표시 · CASE · COALESCE보고서용 표시와 조건별 분류
업무 질문 → 대상 테이블 → 연결 조건 → 행 조건 → 집계 → 출력·가공 → 정렬.
SQL을 작성할 때 확인하는 순서이며 DB의 물리적 실행 순서를 뜻하지 않음.

실무에 적용하기 전 확인

  • 내 업무에 허용된 데이터와 조회 권한 확인.
  • 날짜 범위·금액 단위·NULL의 의미 확인.
  • 결과 한 행이 고객 한 명인지, 계좌 한 개인지 확인.
  • 조인 후 중복 합산이나 누락 여부 확인.
  • 조건을 바꾸어 재사용할 때 결과 건수와 값을 다시 확인.
이제 할 수 있는 일
업무 질문을 구체적인 조회 조건으로 바꾸고, SQL로 확인한 결과를 설명하기.
