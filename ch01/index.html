SQL이란?

SQL은 Structured Query Language의 줄임말. 여기서 쿼리(Query)는 데이터베이스에 보내는 요청으로 이해하면 됨.

1.5 · 엑셀과 데이터베이스

엑셀 vs. 데이터베이스

  • 엑셀: 자료 정리·분석하는 데 활용.
  • 데이터베이스: 업무 데이터를 함께 저장·관리하는 데 활용.
은행 업무에서는 동시 처리·접근 권한·데이터 일관성 관리가 중요함.

왜 테이블을 나누어 저장할까?

고객 연락처를 계좌마다 반복해 저장하면 연락처 변경 시 여러 곳을 수정해야 함.

1.7 · 기본키(PK)

같은 이름의 고객, 어떻게 구분할까?

기본키(Primary Key, PK)는 각 행을 구분하는 기준.

고객번호 PK이름
1001김민준
1002이서윤
1003김민준

“김민준 고객을 찾아주세요.”

이름이 같은 고객이 두 명이므로 특정할 수 없음.

“1003번 고객을 찾아주세요.”

고객번호로 한 명을 정확히 구분할 수 있음.

중복 불가(Unique)

고객 테이블에서 같은 고객번호를 두 행의 기본키로 사용할 수 없음.

+

빈 값 불가(Not Null)

각 행을 구분해야 하므로 기본키는 비워둘 수 없음.

기본키 예
고객은 고객번호, 계좌는 계좌번호, 거래는 거래번호로 구분.
1.8 · 외래키(FK)

이 계좌는 누구의 계좌일까?

외래키(Foreign Key, FK)는 참조하는 키의 값으로 관련 데이터를 연결하는 컬럼.

계좌 테이블의 고객번호(FK)가 고객 테이블의 고객번호(PK)를 참조함.
같은 고객번호를 기준으로 ‘이 계좌가 누구의 계좌인지’ 연결할 수 있음.

고객 한 명 → 여러 계좌

1001번 고객이 A001·A002 계좌를 보유.
계좌 테이블의 고객번호(FK)는 반복될 수 있음.

이름보다 번호로 연결

동명이인이 있어도 고객번호가 같으면 같은 고객을 가리킴.

[핵심] 기본키와 외래키의 차이
  • 기본키: 이 테이블의 각 행을 구분하는 기준.
  • 외래키: 참조하는 테이블의 키와 연결하는 기준.

이 예제의 고객번호(FK)는 고객 테이블에 존재하는 고객번호를 참조함.

1.12 · 확인문제

확인문제

1. 필요한 계좌만 골라 달라고 DB에 요청할 때 사용하는 것은?

정답: SQL. 데이터베이스는 데이터를 보관하는 곳, SQL은 필요한 정보를 요청하는 언어임.

2. 데이터베이스의 역할은?

정답: 정보를 정리해 보관하고 조회. 고객·계좌·거래 등의 정보를 표로 저장하고 연결해 활용함.

3. 고객별 계좌 현황을 요청할 때 더 명확한 표현은?

정답: 고객 한 명당 계좌 수와 잔액 합계를 요청하는 표현. 결과 한 줄의 기준과 필요한 항목이 명확함.

4. 같은 이름의 고객을 정확하게 구분하는 기준은?

정답: 고객번호(PK). 이름은 같을 수 있지만 기본키는 각 행을 고유하게 구분하며 비워둘 수 없음.

5. 계좌 테이블의 고객번호(FK)에 1001이 두 번 나와도 될까?

정답: 가능함. 1001번 고객이 여러 계좌를 보유할 수 있으므로 고객번호(FK)는 반복될 수 있음. 각 계좌는 계좌번호(PK)로 구분함.

6. 계좌 한 개에서 거래 세 건이 발생하면 거래 테이블에는 몇 행이 생길까?

정답: 3행. 거래 테이블의 한 행은 거래 한 건을 뜻함. 세 행의 계좌번호는 같아도 거래번호는 서로 다름.

Chapter 1 정리
테이블은 행과 열로 데이터를 저장함. PK는 행을 구분하고, FK는 관련 데이터를 연결함.
SQL로 필요한 데이터를 찾고, 업무 요청을 구체적으로 표현할 수 있음.
1.13 · 단원 마무리

단원 마무리

데이터의 구조를 이해하고 필요한 정보를 구체적으로 요청하기.

데이터베이스정보를 정리해 저장하고 필요할 때 찾아 쓰는 저장소.
테이블 · 행 · 열테이블은 데이터의 묶음, 행은 데이터 1건, 열은 항목.
기본키 (PK)각 행을 구분하는 값. 중복과 NULL을 허용하지 않음.
외래키 (FK)다른 테이블의 기본키 또는 고유키를 참조하여 관계 연결.
SQL필요한 데이터를 조회하고 조건에 맞게 선택·요약하는 언어.
업무 질문 구체화대상 · 조건 · 출력 항목을 명확하게 정리.
